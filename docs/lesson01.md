# 第 1 课：先把一次预测写对

本课建议用 30–60 分钟。你亲手完成两个小函数：把状态按固定顺序组织起来，计算给定动作后一个时间步的名义状态预测。今天的目标是理解状态、动作和更新顺序；训练网络和规划器是后续课程。

## 1. 场景与状态

一条直线道路，前车和自车同向行驶。第一课假设前车匀速。

状态固定为 `s = (gap, v_ego, v_lead, a_actuator)`：

| 字段 | 含义 | 单位 |
| --- | --- | --- |
| `gap` | 前车后保险杠到自车前保险杠的净间距 | m |
| `v_ego` | 自车向前速度 | m/s |
| `v_lead` | 前车向前速度 | m/s |
| `a_actuator` | 停车约束施加前，自车执行器的加速度响应状态 | m/s² |

`gap <= 0` 表示两车接触或重叠。保留负值用于检查；不能把负间距改成零来掩盖碰撞。任务环境以后会在碰撞时终止回合。

动作 `accel_cmd` 是期望加速度，单位 m/s²。例如 `-2.0` 表示请求制动。它与执行器响应 `a_actuator` 不同，也不是油门、刹车踏板百分比。

为什么增加第四个状态？同样的速度与车距下，车辆可能正在加速，也可能已经在制动；后续速度变化不同。执行器有响应过程，需要记住它当前的状态。

这里的 `a_actuator` 不是在所有边界下都等于 IMU 实测加速度。车已经停下但制动仍保持时，它可以为负，而速度保持零。教学环境显式提供这个状态；将来接 CARLA 时要重新核对可测观测或使用历史估计，不能假装隐藏执行器状态天然可见。

## 2. 本课参数

| 参数 | 值 | 意义 |
| --- | --- | --- |
| `dt` | 0.1 s | 每个离散时间步 |
| `tau` | 0.5 s | 名义执行器响应时间常数 |
| `accel_min` | -6.0 m/s² | 指令下界 |
| `accel_max` | 2.0 m/s² | 指令上界 |

这些是教学设定，不是某辆车的实测参数。配置要求 `0 < dt <= tau`，让这一课的执行器更新成为旧响应与新指令的加权平均；这不是一般数值方法的完整稳定性判据。

## 3. 四个更新方程

先将动作限制到配置允许的范围：

\[
u_t = \operatorname{clip}(a_t^{cmd}, a_{min}, a_{max}).
\]

本课使用前向 Euler。每个右侧都使用时刻 t 的旧状态：

\[
g_{t+1}=g_t+(v_{l,t}-v_{e,t})\Delta t
\]

\[
v_{e,t+1}=\max(0, v_{e,t}+a_{act,t}\Delta t)
\]

\[
v_{l,t+1}=v_{l,t}
\]

\[
a_{act,t+1}=a_{act,t}+\frac{\Delta t}{\tau}(u_t-a_{act,t}).
\]

第一条来自相对速度：前车比自车慢时，`v_lead - v_ego` 为负，间距缩小。第二条把加速度积分成速度；非负约束防止这个跟驰任务里的车辆反向行驶。第三条是本课前车匀速假设。第四条描述一阶执行器响应。

重要约定：更新速度时，不使用刚算出的 `a_actuator_next`；更新间距时，不使用刚算出的速度。其他积分方案可以成立，但那是另一个离散模型，不能混在本课验收里。

前向 Euler 在接近停车、接触时存在离散近似。后续做碰撞边界评估，需要研究步长敏感性和事件处理；本课通过不代表已解决这些问题。

## 4. 手算一个例子

初始状态：`(20.0, 10.0, 8.0, 0.0)`；动作：`-2.0`；使用默认配置。

| 分量 | 计算 | 结果 |
| --- | --- | --- |
| 下一步间距 | `20 + (8 - 10) * 0.1` | 19.8 m |
| 下一步自车速度 | `10 + 0 * 0.1` | 10.0 m/s |
| 下一步前车速度 | 保持匀速 | 8.0 m/s |
| 下一步执行器响应 | `0 + (0.1 / 0.5) * (-2 - 0)` | -0.4 m/s² |

因此第一次预测应得到：`(19.8, 10.0, 8.0, -0.4)`。

继续施加同样的动作，第二次预测应得到：`(19.6, 9.96, 8.0, -0.72)`。

第一步自车速度尚未变化，是本课旧状态 Euler 更新的结果。连续时间的一阶响应并没有凭空多出一个严格的纯延迟；离散步长与积分规则影响了我们怎样近似它。

## 5. 你来写代码

### 练习 A：`LongitudinalState.as_tuple()`

打开 `falconworld/state.py`，只修改这个方法。

- 返回四个字段组成的 tuple。
- 顺序固定为 `gap, v_ego, v_lead, a_actuator`。
- 不修改输入对象，不自行归一化，也不交换两车速度。

字段顺序就是后续数据和模型的接口约定。即使四个数字都正确，顺序错了，网络也会学习到错误的含义。

### 练习 B：`predict_one_step()`

打开 `falconworld/nominal.py`，保留已有输入检查，用本课方程替换最后的 `NotImplementedError`。

建议顺序：读取旧状态；限制输入指令；分别计算四个下一状态值；用它们创建并返回一个新的 `LongitudinalState`。

这里 `frozen=True` 表示状态对象不可原地修改。使用新对象能减少“先更新速度，后面的间距公式却误用了新速度”这样的时序错误。

分层提示：

1. 如果不知道从哪里开始，先把 `gap_next` 写成相对速度乘时间加旧间距。
2. Python 的 `min` 和 `max` 可以实现标量限幅；不需要新装数学库。
3. 你可以直接使用 `state.v_ego` 与 `config.dt` 这样的字段。
4. 返回值必须是 `LongitudinalState`，而不是列表或只返回间距。

## 7. 下一步为什么需要这个函数

后续会建立独立的任务环境，环境的真实响应参数可能不同于名义模型。预测器只能读取公开的观测与动作，不能读取环境参数或未来前车指令。

我们先测量预测误差，再做参数辨识物理基线，然后学习残差。若唯一误差只是固定时间常数失配，线性参数辨识可能已经足够；这时不能把神经网络击败一个故意未校准模型当作研究突破。
