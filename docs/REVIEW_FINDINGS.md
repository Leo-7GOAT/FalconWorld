# 独立代码审查记录

审查日期：2026-10-28。范围：`falconworld/experiments.py`、`planning.py`、`export.py`、`bridges.py`、`run_experiments.py` 及实验协议。只读审查主线；未查看正在运行的 partial test 驾驶指标，未据此选择模型或调参，未重跑耗时闭环。下列行号对应审查时快照，主代理随后修复的代码应另作验证记录。

## 已核验的正确做法

- 预测与 CEM 仅接收当前状态/历史、候选动作。前车脚本仅在 `closed_episode()` 环境推进侧读取。未发现未来前车加速度或真值未来作为模型输入。
- 每次候选评估从同一当前状态出发；执行第一条动作，读取新环境观测后重新规划。普通模型递归自己的预测并更新历史。
- **集成在线风险传播正确地为每个成员维护独立 state/history**（`planning.py:112–122`）。成员不共享均值历史；这与离线 `diagnostics.recursive_members()` 的定义一致。
- ensemble 与 ensemble_risk 共享模型、候选数、优化时域和次数、任务代价、初始条件及回退，仅 risk_weight 由 0 变 1。即使 risk_weight=0，代码仍计算成员分歧，因此两者风险消融没有少算模型的计算优势。
- jerk 使用实际速度差分得到的运动学加速度；停车不直接把内部负执行器状态当成实测加速度。
- standard 的场景 seed 是 `900000 + family*1000 + i + training_seed*10000`，每训练 seed 每族每分布 10 个独立场景，3 个训练 seed 合计每族 ID30/OOD30；模型间相同场景配对。没有把三个训练 seed 上同一场景重复算成 30 个独立场景。
- 完成定义已在协议和代码中公开：无碰撞跑满时长且进度达到前车参考的一半（参考下限 5m）。同时报告碰撞、进度和完成率，不能靠一直停车取得完成。
- ONNX 检查比较完整状态转移、历史更新和递归 30 步，不仅比较一次网络头前向；测试数据用于数值一致性验收，未作模型选择。

## 需处理的实质发现

### P1：恢复指纹不足，允许不同环境或指标代码混入同一实验

证据：`experiments.py:185–190` 的签名包含规划代码和模型 NPZ 摘要，但不包含环境 `data.py`、推理 `models.py` 或自身 `experiments.py`。若只修改前车场景、终止规则、风险参数选择或指标计算，已写入 JSONL 的回合将被跳过，新回合按新语义运行。`profile_models()` 的缓存也只检查一个字段存在，没有与模型/数据/完整配置绑定。

建议：将全部影响环境、推理、指标与控制的源文件摘要、数据摘要、模型摘要、完整任务配置写入不可变 run manifest；恢复前验证。单独给验证计时缓存绑定同一指纹。已有 partial 数据应保留为试跑，在冻结最终源快照后开新目录。

### P1：evaluate 会覆写数据且绕过训练指纹匹配

证据：`run_experiments.py:30` 每次调用 `generate_dataset()`，随后覆盖 run_config；`:40–42` 在 `--stage evaluate` 下无条件 `load_models()`，即使当前 fingerprint 与训练记录不一致。改变 preset/生成代码后评估可能把旧模型与新数据混用，并先覆盖旧数据和开环文件，直到更晚的闭环配置检查才失败。

建议：evaluate 只加载已存在、带摘要的固定数据；先验证训练指纹、数据及预期模型集合，全部匹配后才写结果。不要在验证前修改已有产物。

### P2：共享主机时间与端到端控制周期的标注需要补足

证据：`profile_models()` 为串行验证 profile，而正式 benchmark 可用 4 个进程共享 CPU。随机打乱作业有助于分摊争用，但不能保证每种方法承受相同并发负载。`closed_episode():72–76` 的 sensor_history 在 `planner.command()` 计时之外；`:87` 直接使用规划器返回 cycle_s，漏掉传感状态估计。`summarize():232–233` 平均 episode p50/p95，并非汇集所有控制周期后的总体 p50/p95。

建议：将正式争用条件和 workers 写入结果，称“共享主机负载下周期”。另做独占/受控负载的验证计时作为部署证据。完整控制周期从状态估计前开始，覆盖安全检查和模型/优化；若不含车辆 I/O，应明确。原始逐周期日志可算 pooled p50/p95，同时保留 episode 分布。单 worker profile 选出的候选数只能称验证阶段近似匹配，应报告正式运行的实际预算差。

### P2：时间预算搜索未纳入已测量的最小候选点

证据：`profile_models():134–155` 先测 8 候选，但后续 `best_distance=inf`，二分范围 8–16384 仅 8 次；若所需预算接近 8 候选，搜索最后只能到约 70，已测量的 8 不参与最优选择。这可能错过更匹配的可行候选数。另最小候选 profile 用默认 CEMConfig，若调用者传入不同 horizon/iterations，将与真实预算配置不一致。

建议：把下限测量作为初始最佳点；采用足够收敛精度或粗扫加局部搜索，所有 profile 继承 base_config。候选数只允许依据 val profile 选择，测试前固定；为预算匹配设明示容差，超出时只报告未匹配。

### P2：协议要求的跨训练 seed 分层区间尚未实现

证据：`summarize():243–258` 按 `(family,scenario_seed)` 汇总后直接 episode bootstrap，输出标签称“training seeds averaged”。standard 在训练 seed 间使用不同场景，实际没有同场景跨 seed 平均；同一组模型权重又被多个 episode 共享。当前区间可解释为**给定这三个已训练模型和分配方案的场景抽样不确定性**，但不是训练随机性的层级区间，与协议“跨训练 seed 给分层区间”不一致。

建议：保留目前 conditional episode 区间，修正标签；另外先按 training_seed 重采样、再在 seed 内按配对 episode 重采样，报告只有 3 个 seed 时的不稳定性，或至少列出每 seed 的效果。不把帧或同 seed 的大量回合视为独立训练复现实验。

### P2：规划入口异常未进入已实现的安全回退

证据：`LongitudinalMPC.command()` 先调用模型，随后才执行 `SafetySupervisor.filter()`。只读最小复现使用 horizon=1、candidates=2 的配置，输入 gap=NaN 时 `PhysicsModel` 抛出 ValueError，未返回 `invalid_observation` 回退记录。模型求解异常也会直接使回合退出；当前回退只覆盖返回 NaN cost/空 best 的求解失败。

建议：在优化前校验观测/历史并返回明确回退，包围已知模型数值/形状错误并记录失败原因；对编程错误不要静默掩盖。部署时独立 SafetySupervisor 还应接收完整周期耗时和时间戳，不能仅依赖该规划器内部 gap 回退。冻结实验中有效有限状态不受此入口修复影响，但需新增失败用例。

### P2：观测 bridge 的 dt 参数与估计器固定 dt 不一致

证据：`bridges.observed_history(history, dt=.2)` 接受相隔 .2s、速度从 1 到 1.2m/s 的观测，但内部 `estimate_sensor_state()` 用固定 .1s 计算，输出约 2m/s²，真实差分应为 1m/s²。默认 .1s 的当前主线不受影响，但公开 API 接受了无法正确处理的配置。

建议：既然模型固定 .1s，bridge 显式拒绝其它 dt；或真正按观测时间差估计并按模型周期重采样。SensorWorldModel 预测时间戳也应与同一模型周期绑定。

### P2：集成导出被跳过，不能称全部最终模型均已可部署

证据：`export.validate_exports():96–98` 对 EnsembleModel 直接 continue。成员中的额外两个 history 网络未导出，亦没有集成聚合及风险定义的部署 manifest。现有检查可证明 7 个单模型的 ONNX 数值一致，不能证明 ensemble_risk 的部署一致性。

建议：若最终部署使用单个 history/physical 模型，明确该范围；若使用集成，导出全部成员并验证独立递归历史、均值与分歧的聚合一致性。不要把单模型验证泛化为集成验证。

## 风险信息与完成定义的报告边界

在线 MPC 仅使用 `std(member predicted gap)` 作为启发式风险折减；没有使用 diagnostics 的 val 校准半径。两者应分别命名为“成员分歧风险惩罚”和“离线经验区间评估”。不得宣称在线规划已使用校准置信区间或具备概率安全保证。成员历史独立传播已经正确实现，但不能消除成员共享的结构偏差；OOD 诊断正用于暴露这一点。

`summarize()` 目前可在部分 JSONL 上直接产出正式外观的表/图，没有预期回合数、训练 seed 覆盖和缺失模型检查。建议输出完整性审计（预期/实际/唯一键/重复键/缺失配对），未齐全时显式标记 provisional。报告中的“完成”只代表登记的有限时域任务判据，不能扩展为路线到达、CARLA 通过或实车验收。

长任务恢复另需考虑 JSONL 最后一行被中断时的处理：当前逐行 json.loads 会因残缺尾行整体失败。建议仅允许截去末尾一个不完整行并保存审计副本，其他损坏仍报错；配置和最终汇总使用临时文件原子替换。此项为恢复可靠性建议，不作为已观察到的驾驶性能缺陷。
